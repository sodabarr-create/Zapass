# Как выложить «Запас» на GitHub и сервер

## 1. GitHub

Создайте **приватный** репозиторий. Распакуйте `Zapas-GitHub-source.zip` и загрузите его содержимое в корень репозитория: README.md, app.py, static/ и compose.yaml должны лежать сразу на первом уровне.
В архиве нет токенов, данных магазинов, базы, личных скриншотов и видео. `.env.example` — пустой образец, его загружать можно. Убедитесь, что GitHub показывает зелёную проверку Check project после загрузки.

Не загружайте целиком рабочую папку с компьютера вручную: GitHub Upload files не обязан учитывать .gitignore. Пользуйтесь подготовленным архивом или git, который учитывает исключения.

## 2. Что требуется от хостинга

Linux VPS с Docker Engine и Docker Compose, постоянным диском и доменом. Для небольшого пилота можно начать с 1 CPU / 1 ГБ RAM, затем смотреть фактическую нагрузку. Обычный статический хостинг и GitHub Pages не подходят: бот и база должны работать постоянно.
Откройте входящие TCP 80 и 443; DNS A домена направьте на IP сервера. Если добавлен AAAA, IPv6 тоже должен вести на этот сервер. Серверу нужен исходящий HTTPS к Telegram, Ozon и WB.

## 3. Настройка на сервере

Скопируйте или клонируйте репозиторий, перейдите в его папку. Выполните:

```sh
cp .env.example .env
chmod 600 .env
python3 scripts/generate_key.py
nano .env
```

Вставьте полученный ключ в ZAPAS_MASTER_KEY. Это пароль шифрования: сохраните его отдельно в менеджере паролей. Его потеря означает потерю доступа к сохранённым API-ключам.
В .env заполните DOMAIN (без https://), ZAPAS_WEB_ORIGIN (https://ваш-домен), TELEGRAM_BOT_TOKEN (токен из BotFather), TELEGRAM_CHAT_ID (числовой Telegram ID владельца). Не отправляйте .env в GitHub, чат или скриншот.

```sh
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Дождитесь состояния healthy у app. Откройте https://ваш-домен — страницу входа, затем https://ваш-домен/miniapp — оболочку Telegram-приложения. В обычном браузере Telegram-вход не подтверждается: для него откройте приложение кнопкой бота.
Caddy получает сертификат HTTPS автоматически после правильного DNS и доступности портов 80/443.
Порт 8765 — локальная панель без публичного входа; он намеренно не опубликован. Не добавляйте его в ports и не направляйте на него прокси.

## 4. Переключение Telegram-бота

Остановите прежний локальный запуск бота и временный туннель на компьютере: один токен должен обрабатываться только одним сервером. После запуска HTTPS выполните:

```sh
docker compose exec app python scripts/configure_bot.py
```

Скрипт обновит команды и кнопку приложения на постоянный адрес. Существующий webhook не удаляется: при конфликте скрипт остановится. В BotFather проверьте адрес Main App, если вы отдельно его настраивали: https://ваш-домен/miniapp. Старые сообщения содержат старые ссылки — отправьте /start заново.

## 5. Существующие данные с Windows

Архив намеренно запускает новый экземпляр без личной базы. Старый локальный экземпляр и его данные остаются на компьютере. Ключи старой версии зашифрованы Windows DPAPI: копирование базы на Linux их не расшифрует. Для пилота проще подключить магазины заново. Для переноса истории нужна отдельная проверяемая миграция, не заменяйте базу вслепую.
Новые ключи Linux шифруются ZAPAS_MASTER_KEY и хранятся в Docker-томе app_data, вместе с базами отдельных пользователей.

## 6. Резервные копии и обновление

```sh
docker compose exec app python scripts/backup.py
mkdir -p backups
docker compose cp app:/data/backups ./backups/server
```

Храните копии вне VPS; ключ шифрования и .env сохраняйте отдельно, в защищённом месте. Сначала сделайте копию, затем обновляйте код:

```sh
git pull
docker compose up -d --build
```

Если код был загружен без git, сначала клонируйте репозиторий либо заменяйте только исходники, сохраняя .env. Никогда не запускайте `docker compose down -v`: флаг -v удаляет постоянные тома с данными.
Для восстановления остановите app, восстановите базы в /data с правами пользователя 10001 и прежний ZAPAS_MASTER_KEY, затем запустите app. Первое восстановление проверьте на отдельном экземпляре.

## 7. Проверка перед приглашением тестировщиков

- По домену открывается сайт с действительным HTTPS.
- /start и кнопка приложения работают на телефоне и компьютере.
- Два тестовых пользователя видят только свои данные.
- Подключение реального магазина завершает загрузку без ошибки; демо не выдаётся за реальный магазин.
- Фактические остатки и расчёты сверены с кабинетом продавца, уведомление приходит в правильный чат.
- Проверены резервная копия и восстановление.

Автотесты проверяют логику, но не заменяют проверку настоящих API и доставки Telegram. Docker на текущем компьютере не установлен: сборка контейнера будет дополнительно проверена GitHub Actions. Подготовка исходников сама по себе не публикует сайт.
Платежи выключены по умолчанию. Реальный эквайринг и тариф пока не запускайте. Telegram-демо и самостоятельные веб-аккаунты сейчас имеют разный доступ: не обещайте полноценное подключение магазина каждому пользователю Telegram до проверки этого сценария.
Запускайте один экземпляр app: несколько копий с одним Telegram-токеном будут конфликтовать.

Официальные справки: [Docker Compose](https://docs.docker.com/compose/), [автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https).
